# Б28 «Умная кухня»

Учебный прототип. Python + SQLite + Streamlit: SQLite не требует сервера; интерфейс запускается локально. Холодильники моделируются общей БД; информация о кухонных принадлежностях привязана к холодильнику как условному представителю владельца. Число людей служит справкой, число порций задаётся отдельно. Демо-данные и тексты синтетические.

## Запуск (Windows PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python db.py
streamlit run app.py
```

Нужен Python 3.10 или новее. Если PowerShell запрещает активацию, используйте `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`, затем `.\.venv\Scripts\python.exe -m streamlit run app.py`. При первом запуске создаётся kitchen.db. Инициализация повторно не добавляет демонстрационные строки. Для сброса закройте приложение и удалите только файл `kitchen.db`: `Remove-Item .\kitchen.db`; следующая инициализация создаст его заново. Это удалит также все внесённые пользователем данные.

Команды тестирования приведены в разделе «Проверка».

Конвейеры A и B работают офлайн на регулярных выражениях. Конвейер C вызывает LLM по OpenAI-совместимому протоколу `chat/completions`; конечная точка задаётся переменными окружения:

```powershell
$env:KITCHEN_LLM_BASE_URL = 'https://routerai.ru/api/v1'   # или локальный ollama: http://localhost:11434/v1
$env:KITCHEN_LLM_MODEL = 'z-ai/glm-5.3-flash'              # для ollama, например, qwen2.5:3b-instruct
$env:KITCHEN_LLM_API_KEY = '...'                            # для локального ollama не нужен
```

Без переменных окружения по умолчанию используется локальная точка `http://localhost:11434/v1` (ollama, модель qwen2.5:3b-instruct); при недоступности сервиса приложение сообщит об ошибке. Модель по few-shot подсказке возвращает JSON-массив кандидатов фактов (название, порции, ингредиенты, время, температура, правила «если/то», действия, посуда, шум); код нормализует названия и единицы (кг→г, л→мл) теми же функциями, что и эвристики, отбрасывает некорректные элементы, после чего факты сравниваются с ранее сохранёнными и попадают на ручное подтверждение. LLM может ошибаться и дополнять текст не обязана — все факты остаются кандидатами.

Чекбокс «Классификатор строк (XNLI)» действует только для A/B: он добавляет к каждой строке zero-shot классификацию joeddav/xlm-roberta-large-xnli, не извлекая ингредиенты и правила. Для него установите `python -m pip install transformers torch sentencepiece` и заранее загрузите модель командой:

```powershell
python -c "from transformers import AutoTokenizer, AutoModelForSequenceClassification; n='joeddav/xlm-roberta-large-xnli'; AutoTokenizer.from_pretrained(n); AutoModelForSequenceClassification.from_pretrained(n)"
```

Требуются интернет при первом скачивании, место на диске и ресурсы для большой модели. Значение score — оценка классификатора, а не проверенная вероятность достоверности факта. Проверяйте совместимость версий библиотек и лицензию модели перед использованием.

## Подбор

Выберите холодильники, событие и порции. Каждый ингредиент масштабируется пропорционально, партии суммируются; просроченные исключаются, неизвестный срок отмечается. У одного продукта допускаются разные партии. Проверяются общие доступные принадлежности. Для выбранного меню потребности складываются до вычитания запасов, поэтому один продукт не расходуется дважды. Список можно сохранить в БД как черновик; заказ в магазин не отправляется. Единицы: кг→г, л→мл, штуки→шт. Масса, объём и штуки между собой не переводятся. Синонимы ограничены словарём в recommend.py; при несовпадении единиц нужен ручной разбор.

Примеры: Аня, завтрак, 2 порции — каша готовится; Аня и Борис, обед, 2 — рис с помидорами готовится из запасов обоих; Аня, обед, 2 — потребуется 100 г риса и 200 г помидоров. Аня и Борис, вечеринка, 2 — не хватает хлеба, сыра и духовки. Неизвестный срок требует проверки.

## Тексты и проверка

На вкладке анализа введите или загрузите UTF-8 текст, укажите общее название блюда и источник, выберите конвейер A, B или C. Для учебного формата используйте строки `Название: Каша`, `2 порции`, `овсянка 100 г`, `Если смесь закипела, то варите 10 минут`. Файлы example1.txt и example2.txt содержат специально конфликтующие сведения. Обработайте оба под одним названием: разные количества овсянки и следствие правила (а в конвейерах A/B ещё и время) показываются как возможные конфликты, а не доказанные противоречия. example3.txt — связный текст свободной формы: эвристики A/B извлекают из него лишь пару чисел, посуду и одно «действие» строкой целиком, тогда как конвейер C распознаёт название, порции, ингредиенты с количествами, посуду и правило. Разбор распознаёт простые явные формулировки; для каждого результата сохраняет исходную строку, тип, значение, источник, статус и, только для модели, score. Ручное подтверждение или отклонение меняет статус в БД знаний. Оно не создаёт автоматически рецепт для подбора; рецепт добавляется отдельно после проверки.

Проверка конфликта сравнивает одинаковые названия блюд и продуктов, нормализованные единицы, числа и буквально одинаковые условия правил. Она не вычисляет пересчёт на порции, не устанавливает тождественность этапов и не доказывает несовместимость действий: различия помечаются как возможные конфликты. Отсутствующие данные не позволяют сравнить факты. Сходные названия, разные порции, единицы и этапы проверяет человек. Конфликт не блокирует кнопку подтверждения; решение остаётся за пользователем.

## Проверка

```powershell
python -m unittest -v
python evaluate.py
```

Тесты проверяют масштабирование, кооперацию и исключение холодильников, нехватку продуктов и посуды, просрочку, нормализацию, неверный ввод, конфликт и конвейер C (сетевой вызов подменяется заглушкой, поэтому тесты проходят офлайн). На Python 3.14, 6 ноября 2026 года выполнено 10 тестов, все прошли. Скрипт оценки запущен: A и B — TP=17, FP=0, FN=0, precision=recall=F1=1.0. Единица измерения здесь — наличие типа факта в документе, а не точность извлечённых значений. Это четыре специально составленных учебных примера, использованных при разработке; результат не показывает качество на новых рецептах. Порядок A/B меняет последовательность вызовов извлечения сущностей и связей, но независимые этапы не влияют друг на друга; равные результаты ожидаемы и не доказывают эквивалентность других конвейеров. Время не измерялось. Для содержательного эксперимента подготовьте отдельную независимую разметку значений и правил, разметьте реальные конфликты, сравните найденные и пропущенные случаи и измерьте время.

Живой прогон конвейера C (6 ноября 2026, модель z-ai/glm-5.3-flash через routerai.ru): три учебных текста обработаны за 33 с; между example1 и example2 найдены два возможных конфликта (количество овсянки 100/200 г и разные следствия одинакового условия); из свободного текста example3 извлечены название, порции, три ингредиента с количествами, посуда, действия и правило. Прогон демонстрирует работоспособность, но не является метрикой качества: результат зависит от доступности сервиса и версии модели.

## Ограничения

Эвристики не обрабатывают надёжно свободный язык, опечатки, OCR, сложные единицы, отсутствующие количества, порядок и причинность без явного «если …, то …» — для этого предназначен конвейер C, но качество LLM не гарантировано и требует сервиса (облачного или локального). Выявление времени и температуры относится к строке, а не к конкретному действию. Нельзя автоматически перенести результаты анализа в структурированный рецепт. Нет управления запасами через интерфейс, реальных магазинов, авторизации или сетевых холодильников. Веб-интерфейс требует установки зависимостей; его фактический запуск в среде подготовки не проверялся. Тесты создают записи анализа в текущей БД; для демонстрации используйте отдельную или сброшенную БД.
